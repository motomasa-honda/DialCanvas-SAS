# ADR-0004: 外観と7軸独立交換を維持した既製品優先構成

- 登録日：2026-10-19
- 状態：既製品優先の設計方針を採用。列挙する個別部品は評価候補であり、製造採用・購入承認ではない。
- 起点：PR #2のHEAD `a16c67b52d4ff6338fb7d829bec0ebfdea18bcff`

## 背景

ユーザーは完成を早めるため、既存設計も含め、既製品で代替できるところと完成イメージ維持に必要な専用部品を全体的に見直すよう指示した。M1はすでに市販I/O拡張2枚と市販ドライバー7枚を使う方針だが、USB-C受電、常時3.3V、照明基板、保持部材などに個別設計が残る。

初期要求のモーター1個案は、後続の確定A案（7軸ドライバーを歯車/P3/他6軸を外さず個別交換）と異なる。初期画像の寸法や表示器サイズも後続基準と区別する。

## 決定

1. 外部電源、USB-C受電、3.3V変換、RTC、照明等は完成モジュール/標準部材を先に適合評価し、同等品が使える機能の個別IC・フットプリント設計を第一選択にしない。
2. 3.4型800×800 Waveshare候補、7軸独立ドライバー、現在のファームウェア資産を優先して継続する。全軸一体化、単一モーター回帰、別SBCへの移行は採らない。
3. 専用製作の中心は、木部と透かし、ベゼル/アクセント、装飾歯車の外観円板、共通カセット/取付アダプターと固有ソフトとする。ハブ、軸受、ねじ、基板、圧着線等は既製品を使う。
4. 安全機能も適合する完成モジュールが使えるなら利用する。ただし独立停止、故障ラッチ、手動復帰、低電圧/MCU停止/逆給電等の同等性を確認し、満たさないものだけを接続/安全基板へ残す。基板枚数や全部品数の削減量は未確定。
5. 新候補の同等性が未確認の間、旧回路/CAD/コードを残す。モーターeFuse EN LOW、相出力抑止、遠隔START/CLEAR禁止、製造ゲート0/6を維持する。

## 具体候補と採用条件

[全体監査](../docs/02-architecture/module-first-audit-2026-10-19.md) と [機械可読データ](../docs/02-architecture/module-first-audit-2026-10-19.json) に記録。USB-Cはコネクタ形状だけで容量が決まらない。5Aケーブルは5A供給/PD契約を保証せず、5V級専用源と受電基板の適合が要る。5V DCジャック電源は背面意匠差のある代替として保持する。

## 影響

- 回路の置換前にモジュール境界（型番/改版/ピン/電圧/電流/外形）を確定し、その後のKiCad回路と保持/配線を再検証する。
- 旧版のERC/DRC・幾何検査・DONE_SCOPEを新版の合格に転用しない。今回は設計方針と調査のみで、48件の状態・完了数は変えない。
- 既存FG-021/025等の初期記載を、既に確定していた後続A案と現行候補へ同期する。旧Phase 0 v0.7文書とADR-0002本文は履歴として保存する。
- 個別の部品価格だけでなく、工具、PCB実装、送料、改修ソフト、保持部品、保守性を含めて比較する。価格・工期短縮を数値で保証しない。

## 代替案

- 個別ICで全面設計を続ける：高密度化の余地はあるが、個人の1台製作には組立/修正負担が大きい。完成モジュールで実現できない範囲に限定する。
- 市販時計や大型SBCへ全面移行：表示/安全/機構の既存成果を作り直すため今回は推奨しない。
- 既製モジュールだけで全安全機能も完了扱いにする：同等性未確認なので採らない。
