# 安全な移行計画

1. 開始 SHA とクリーンな作業状態を [調査記録](existing-assets.md) に固定し、専用ブランチで資料のみ追加する。
2. 旧 `docs/requirements/DC-000/` とカテゴリ別 README は移動しない。新資料から必要な箇所へ相対リンクを張る。
3. 文字盤意匠の原本、承認済み外観画像、旧コードが後日提供されたら、出典・ライセンス・ハッシュを記録して再利用可否を再判定する。
4. Phase 1 で実装が必要になった時点で `hardware/`、`firmware/`、`web/`、`dialcanvas/`、`assets/` を実体と同時に作る。新旧の同義ディレクトリを無理に統合しない。
5. 既存の Git 履歴、Issues、Releases、default branch、リポジトリ名を変更しない。現段階の作業をリモートへ反映する場合は差分レビュー後に行う。

今後、ファイル移動が必要なら、参照リンクとビルド・テストの影響を確認して個別 ADR に理由を残す。今回の移行は既存ファイルの削除・移動を含まない。
