# 既製DC/DCによる常時3.3V回路と全負荷予算

2026-10-19。対象：G1-05/G1-06、G4-04、G3-06、G5-07。**無通電の代替回路候補。製造・発注・フラッシュ・通電の承認ではない。**

## 実装した変更

G1-95の個別TPS62933回路（IC、L、R2個、C7個の11部品）に対し、Pololu D24V5F3 #2842完成モジュール1枚を使う別候補を実装した。旧G1-95は比較原本として変更しない。

`build_review.py` はG1-94までの618端子を再生成し、その接続を変更せず、実在モジュールのVIN/GND/VOUT/SHDNと入力接続点2個を追加する。624端子、184記号。旧648端子/194記号との差は回路候補の置換によるもので、製造BOMの総削減数ではない。生成物には編集可能なKiCad回路、シンボル、接続JSON、CSVを含む。

| 接続 | 行先・条件 |
| --- | --- |
| U46 VIN | `B77__5V_RAW`。モーターeFuse入力より上流 |
| U46 GND | 共通GND |
| U46 VOUT | `3V3_AON`。既存安全ロジック・外部I/O等の常時電源 |
| U46 SHDN | NC。メーカー記載のVINへの内部100kΩプルアップで常時動作。MCUやモーター電源に接続しない |
| J20 1/2 | DC入力の正極/帰路という接続境界。実ジャック、保護、幹線の型番・定格は未確定 |

モジュールの「ピン番号」は基板印字の端子名をそのまま使う。メーカーが番号を付けていない端子の数値順序やフットプリントを捏造しない。ヘッダー位置・向き・保持・接続仕様はG2-03/G4-04で残る。

eFuse ENのGND抑止、28相のOE抑止、独立ラッチ/復帰条件を変更しない。3.3Vをモーター側5V_MOTORから作らず、モーター停止中も監視回路を維持する。未実装入力を駆動済みと偽装するPWR_FLAGは追加しない。

## 電力予算の扱い

`components.json` を原本に、`power_budget.py` が計算する。一次資料の掲載値、概数からの計算、未取得の実機値を分離する。

5V、各軸1相という条件では、コイル概算7×5/42≒0.833A、LED長さ比例≒0.267A、ファン掲載定格45mAの小計は**1.145A**。ドライバー電圧降下、巻線公差、LEDの電圧依存、ファン始動/拘束などを含まない。最大保証電流ではない。

| 電源の掲載電流 | 20%余裕を除く負荷枠 | 小計を引いた残りの机上枠 |
| --- | --- | --- |
| 3A | 2.4A未満 | 約1.255A未満 |
| 5A | 4A未満 | 約2.855A未満 |

この残りに、表示基板、ドライバー回路、外部3.3V系の変換入力、その他負荷、掲載定格を超えるピーク等を含める。現時点の結論は**5A候補を優先比較するが、容量合格とはしない**。

- WaveshareはP4/C6/LCD/内部電源を含む5V負荷として1回だけ計上する。
- 外部3V3_AONは別負荷。入力換算は `V_AON最大 × I_AON最大 / (V_RAW最小 × 効率最小)`。メーカーの典型効率80–93%を保証最小効率にしない。
- モーターコイルとドライバー基板の表示LED/入力回路消費を別計上する。
- ファン45mAを始動・拘束ピークとして使わない。
- 入力容量はアダプター、ジャック、保護、線材の最も小さい定格で制限する。5A源を選んだだけでXH1接点に5Aを流さない。
- 既存eFuseの2.21kΩ設定の保証最小値は未知のまま。5Aアダプターへの変更はモーターeFuseの余裕を増やさない。

`evaluate_bounds` は全負荷値が明示された場合の数値スクリーニング用であり、証拠受付や通電許可の経路ではない。入力の部品定格/電圧範囲が未確定ならHOLD、過電流/電圧不適合はFAIL。全数値が適合しても結果はCONDITIONALのみ。実測値は既存の根拠付き受入手順で別途審査し、コードへの入力だけで採用しない。

## 再現と検証

```sh
python3 execution/cots_power/build_review.py
python3 execution/cots_power/check_contract.py --generated execution/cots_power/generated
python3 execution/cots_power/test_power_budget.py
python3 execution/cots_power/power_budget.py --output execution/cots_power/generated/power_budget.json
```

ローカル：原回路接続保持、上流AON/EN/OE抑止、全負荷の欠測/入力定格不足/過電圧・瞬低の検出を確認。標準KiCad CLIはこの環境にない。apt導入も実行環境の権限制約で利用できず、ローカルnative ERCとは記録しない。

関連する既存G1-95ワークフロー1本に代替回路のnative netlist/ERC/SVG処理を追加し、同じKiCad導入を共有する。旧G1-95のERC3件は旧版のまま照合し、新候補は未実装入力/帰路のERC2件を**予想される未解決条件**として照合する。CI実行前にこの予想を実測結果とは記録しない。ERC検査で全不具合を無視したり、完了扱いにする変更はしない。結果・SHAは対応PRのチェック履歴で確定する。

PCB/フットプリント/DRC/実機試験は未実行。48項目の状態は今回変更せず、製造ゲートも閉じない。

## 後続工程

1. 完成表示基板の入力ピーク、外部AON全負荷、同一改版ドライバーを確定する。負荷値取得には別途、承認された安全な試験計画が必要。
2. 実ジャックと入力保護・幹線を選び、DC入力の正極/帰路を実端子として描く。全負荷の電圧適合を確認した後で電源方式を確定。
3. 3.3Vモジュールの実負荷/立上り/崩壊/監視しきい値を照合し、回路の供給源に関する残りのERCを解消する。
4. モジュール境界に合う保持・ハーネスへ反映し、必要な専用安全/接続基板だけをPCB化する。
