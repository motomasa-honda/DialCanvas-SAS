# G1-82 実KiCad9検証ゲート

元のG1-82 CIは364端子のPython静的検証のみであり、KiCad自身に読み込ませていない。その欠落を解消するため独立の `g1-82-kicad-native-erc.yml` を追加した。Ubuntu24.04に公式KiCad9 PPA版を導入し、native XML netlist・SVGの生成およびERC JSONの生成を試みる。成果物はGitHub Actions artifactに保存され、後続の正規部品置換時の差分比較に用いる。

- **ゲートの意味を分離する:** native形式パーサー・エクスポートの成功と、電気的ERC違反0件は全く別の主張である。ERCに違反が残っても本workflowは設計を合格認定しない。仮想部品98個は全てPCB非実装指定であり、部品のピン電気種別もpassiveのためERC成功で実配線安全性を主張できない。
- **禁則:** G1-77/78/81の実配線元ネットおよびeFuse U7.EN 10k GND、28相OE HIGHを変更しない。KiCad ERCレポートの警告を抑制/除外して合格としない。製造0/6、19/48は維持。
- 実行後、ジョブログとダウンロード可能な native evidence をレビューし、エラーが発生した場合は先に回路図の構文/登録漏れを直す。

## G1-83 — KiCad9 ERC問題の修正（グリッド・ライブラリ）

初回native KiCad9.0.9で364端子/104ネット/98部品の実XML生成に成功したが、**580件のERC指摘**が出た（端子・配線グリッドずれ462警告、FG_REVIEWライブラリ未登録98警告、単端子ラベル20エラー）。編集可能KiCad原本の364結線は保ったまま、全オブジェクトを50mil接続グリッドへ再配置し、FG_REVIEW.kicad_symとsym-lib-tableを追加。

`validate_native_netlist.py`はKiCad CLI自身が出したXMLから364端子のピン番号とネット名を一つずつ元JSONと突合し、原本と電気的に違う接続ならCI不合格。未使用端子と未設計ピン20件は**ERC隠蔽しない**。認定済みの正規メーカー記号・footprint・ERCゼロを主張しない。製造0/6、19/48のまま。

## ヘッドレスKiCad9の実ライブラリ解決

実ERC再試行で接続グリッドずれ462件は0件に低下し、98ライブラリ参照は残存（headless `kicad-cli` はプロジェクト登録表だけでは認識できなかった）。公式マニュアルのプロジェクトテーブル取扱いを踏まえ、CIランナーの**一時的なユーザーグローバル `sym-lib-table`** にリポジトリ内の正本 `FG_REVIEW.kicad_sym` の**絶対パス**を登録する。これはERC警告の無効化ではなく、真正の参照先ライブラリを読ませる対処。
